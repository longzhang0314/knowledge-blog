# 分布式一致性方案对比

## 选择思路

一致性方案不要脱离业务场景。先判断是否允许短暂不一致，再看失败补偿是否可接受，最后选择实现复杂度可控的方案。

| 方案 | 适合场景 | 代价 |
| --- | --- | --- |
| 本地消息表 | 订单状态通知、异步任务 | 需要补偿和清理 |
| 事务消息 | 本地事务和消息发送一致 | 依赖消息中间件能力 |
| TCC | 强业务约束、可预留资源 | 业务侵入高 |
| Saga | 长流程、多服务编排 | 补偿逻辑复杂 |

## 输出建议

描述方案时补充失败场景：消息发送失败、消费失败、补偿失败、重复消费、下游超时。
