# 后端架构设计表达框架

## 结构

1. **背景和目标**：业务要解决什么问题，核心指标是什么。
2. **约束和现状**：数据量、并发量、团队成本、历史包袱。
3. **方案设计**：模块拆分、数据流、核心接口、关键中间件。
4. **风险兜底**：降级、限流、补偿、监控、回滚。
5. **演进路径**：第一版做到哪里，后续如何扩展。

## 面试表达

先给结论，再讲取舍。不要直接堆技术名词，而要说明为什么这个方案适合当时的业务约束。
