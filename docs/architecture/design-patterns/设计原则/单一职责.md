### 单一职责
1. 原则：一个类或者模块只负责一个职责或只完成一个功能。
2. 目的：实现代码高内聚，低耦合，提高代码复用性，可读性，维护性。
3. 如何判断类的职责是否单一：
- 代码行数过多，函数或属性过多；
- 类依赖的其他类太多；
- 有太多的私有方法；
- 比较难给类起名；
- 类中大量方法都是操作其中某几个属性，这样就可以单独把这几个属性和方法拆分出去。
4. 类的职责是否越单一越好：不是，有些需要管理的功能如果拆分出去，会降低可维护性。
