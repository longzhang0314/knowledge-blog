# Redis产生的由来

Redis产生的由来

查询速度提升过程：

一：随着文件变大，查询速度变慢。为什么？

需要对文件进行全量IO，受硬件影响肯定慢

1. 寻址时间：

秒 > 毫秒 > 微秒 > 纳米

磁盘：ms

内存：ns

2. 带宽：1s可以读多少内存

磁盘：百兆

二：数据库对查询进行加速（分治思想）

一个datapage 4kb（可调节），把全量IO分成不同的数据页，提高查询效率

每4k一个数据页，作为一个窗口，提高寻址效率。

三：建表时需要对字段定义schema

这样就不需要维护行级索引，每行所有字段宽度一定，直接跳跃查找（base+offset）即可。（varchar存储的是对象的地址值）。

四：对表建立索引（路由）

为什么建立索引会提速

1. 索引占据的数据空间小于需要查找数据的大小，可以快速定位；

2. B+Tree的树干在内存

（1）先找到索引所在的data page，读到内存；

（2）通过索引找到id，再找到对应的数据，读到内存。

两次IO就可以找到数据。

五：数据库数据量变大

1. 增删改会随着数据量变大，维护索引结构等问题导致变慢；

2. 命中索引的简单查询，查询速度不会受太大影响；

3. 但是一旦并发量变大，不同用户查找到的内容需要放回内存，会受到带宽限制（磁盘IO影响）。

六：产生了内存关系型数据库（价格过高）

七：热点数据放入内存型数据库（redis, memcache）

为什么Redis, memcache为什么是（key, value）型的？

（1）数据放在磁盘中数据量过大会效率变低，但是全量数据放入内存会很贵。

（2）关系型数据库存在约束，导致数据粒度太小。所以直接采用key=value型。

（3）key=value查询速度快
