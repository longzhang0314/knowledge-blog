# Redis为什么快？

参考：https://zhuanlan.zhihu.com/p/360335981

1.纯内存kv操作

Redis是把整个数据库加载到内存中进行读写，然后定期flush到硬盘中；

2.单线程操作

Redis分为网络请求模块、索引模块、存储模块、高可用集群支撑模块、数据操作模块等。

目前所说的单线程，指的是网络IO和键值对读写是单线程的，指的是网络请求模块和数据操作模块。

4.0开始对部分命令做了多线程化，主要体现在大数据的异步删除功能。

为什么Redis最初设计的时候不需要多线程？

多线程的目的：通过并发的方式提升IO利用率和CPU利用率

但是Redis基于内存，所以CPU不是瓶颈，不需要通过多线程提高CPU利用率

提升IO利用率确实有必要，但不是只有多线程这一种方式。

多线程的弊端：

共享资源的并发控制问题，为解决这些问题，给语言和框架带来了较高的复杂度；

多线程上下文切换带来的性能损耗；

Redis 4.0之前使用单线程的优势：

操作简单，没有锁竞争，没有死锁，没有上下文切换带来的性能损耗等，其实主要是下面两个原因：

（1）Redis的大部分操作都是在内存中完成的，并且使用了高效的数据结构：例如hash表和跳表；

（2）避免多线程竞争，省去了多线程带来的时间和性能开销，并且不会出现死锁。

（3）采用I/O多路复用处理大量客户端的Socket请求，因为这是基于非阻塞的I/O模型，就可以让Redis高效地进行网络通信，I/O读写也不再阻塞。
