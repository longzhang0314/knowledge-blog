#### 为什么查询速度会慢？

1. 查询消耗时间的地方：网络，CPU运算，生成执行计划，锁等待，**调用存储引擎检索数据**（内存操作、CPU操作、IO操作）。
2. 慢查询原因是有一些不必要的额外操作、或者某些操作被额外重复了很多次、某些操作执行太慢。

#### 优化数据访问

- **如何分析一条sql查询语句是否合理**：
    - 确认是否检索了大量不需要的数据，包括行或者列；
        - 查询不需要的数据，比如客户端只需要10条数据，我们先从mysql中查出100条，再返回 （查询后面加LIMIT）；
        ```java
        Bean bean = mapper.selectList().get(0);
        ```
        - 单表或多表关联时查出所有的列（无法用到覆盖索引）；
        ```java
        EXPLAIN SELECT pay_type, create_time FROM t_am_payment_bill WHERE trade_status = 'TRADE_SUCCESS';
        比如项目中大量使用mybatisplus的地方都是直接查所有列，
        但是单表查询的话具体还需要结合开发效率权衡。
        ```
        - 重复查询相同的数据
        
        对于热点数据可以使用缓存。
        
    - 确认MySql服务器层是否存在扫描额外的记录。
        - 响应时间
        - 扫描行数和返回行数
        ```sql
        EXPLAIN SELECT pay_type, create_time FROM t_am_payment_bill WHERE pay_status = 'SUCCESS';
        ```
        一般关联查询可以接受的扫描行数和返回行数的比在1:1和10:1之间；
        
        增加扫描行数和返回行数比例最有效的方法是增加一个合适的索引。
- **重构查询的方式**   
    - 查询切分：
    
      mysql内部查询效率很高，但是如果数据量过大，返回给客户端就会很慢；

      mysql从设计上让连接和断开都很轻量，所以返回小的查询结果很高效。
      
      可以防止一次锁住很多数据，耗尽系统资源，阻塞其他查询。
      
      避免一次给服务器过大的压力。
      
      减少锁的持有时间。
      ```java
      int rows = 0;
      do &#123;
          "DELEVT FROM t WHERE ... LIMIT 10000"
      &#125; while (rows > 0);
      ```
      同时需要避免过度优化。
    - 分解关联查询的条件或优势：
    
      对需要缓存的数据可以拆分出来，比如A表的a字段，这样就可以不用把A表写在关联查询中；
      
      执行单个查询可以减少锁的竞争；
      
      应用层关联，方便后期对数据库进行拆分。
      
      查询效率可能会提升。（前一个表查出的数据作为下一个表的条件，减少Mysql中关联时可能需要重复访问某些数据的情况。）
