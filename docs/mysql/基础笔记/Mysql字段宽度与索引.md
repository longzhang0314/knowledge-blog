### Mysql字段宽度与索引
- 字段宽度：

整数类型：字段宽度是显示宽度，如果当前存储数据宽度小于宽度，前面的位会补0存储；如果超过指定宽度，依然会显示；整数类型字段占据的空间大小与宽度无关，只与整型本身占据的大小有关，比如int 4byte。整形宽度无需优化。

浮点数类型：float,double字段宽度为最大可显示宽度，可能会导致精度损失，一般使用decimal。

varchar类型：字段宽度为最大可显示宽度，超出范围会导致字符被截取，新插入的数据超过最大宽度会报错；如果存储字段小于字段宽度，不会造成空间浪费，但如果是需要用来建立索引的字段，不推荐使用过大宽度。

char类型，基本与varchar一致，但是存储字段过小会导致空间浪费，没有自适应的机制。存储一定长度的字符串时，如果字符长度在255以下，varchar会额外占用1个字节存储长度信息，否则使用两个字节存储长度信息。

---
- 建立索引的几条原则（InnoDB）：
1. 单个索引不能超过767byte,一般认为255字符，当索引长度超过时，如果是唯一索引会失败，普通索引会截取前255个字符。
2. 建立索引的列一般不建议设置过大的宽度，会降低查询效率。
3. 可以通过对过长字段的列建立前缀索引，自定义索引的长度，可以达到一个page页中能够多存储几个索引的目的，但同时模糊筛选可能也会降低效率，需要根据具体业务进行权衡。
```sql
ALTER TABLE table_name ADD KEY(column_name(prefix_length));

其中prefix_length就是当前索引取的字段长度
```
